# Документация проекта «Урви»

## 1. Краткое описание

«Урви» — HTML-прототип сервиса для поиска вещей, которые отдают бесплатно рядом с пользователем. Проект показывает концепцию российского аналога Snag: агрегатор бесплатных объявлений с лентой, категориями, поиском, картой, карточкой объявления, демо-подпиской и сценарием бронирования.

Текущая реализация — статический frontend-прототип в одном HTML-файле без сборки. Источник объявлений подключён к Supabase: страница читает таблицу `public.listings` через Supabase REST API.

## 2. Файлы проекта

| Файл | Назначение |
|---|---|
| `urvi-prototype.html` | Основной интерактивный прототип. Внутри находятся HTML-разметка, CSS, мок-данные и JavaScript-логика. |
| `Snag_разбор_и_российский_аналог.md` | Продуктовый разбор Snag и концепция российского аналога, включая позиционирование, монетизацию и варианты названия. |
| `PROJECT_DOCUMENTATION.md` | Текущая документация по проекту. |
| `prepare_supabase_seed.js` | Одноразовый скрипт нормализации объявлений из HTML и CSV для загрузки в Supabase. |
| `supabase_seed_listings.json` | Подготовленный JSON seed-набор объявлений. |
| `supabase_seed_listings.sql` | SQL seed-набор, сгенерированный как резервный вариант загрузки. |

## 3. Как запустить

Проект не требует установки зависимостей.

### Вариант 1: открыть напрямую

Откройте файл `urvi-prototype.html` в браузере.

### Вариант 2: запустить локальный сервер

Если браузер ограничивает загрузку внешних ресурсов или удобнее тестировать через URL, можно запустить простой сервер из корня проекта:

```bash
python3 -m http.server 8000
```

После этого открыть:

```text
http://localhost:8000/urvi-prototype.html
```

## 5. Продуктовая идея

Сервис решает задачу быстрого поиска бесплатных вещей рядом:

- мебель, техника, детские товары, одежда, растения, животные и прочее;
- привязка к районам Махачкалы;
- единая лента вместо ручного мониторинга разных площадок;
- карта для оценки близости;
- платная надстройка «Урви+» для скорости: бронь, уведомления, радиус и отсутствие рекламы.

Важный продуктовый принцип из исходного разбора: базовая лента должна быть бесплатной, а монетизация должна продавать удобство и скорость, а не просто доступ к чужим бесплатным объявлениям.

## 6. Основные пользовательские сценарии

### Просмотр ленты

1. Пользователь открывает страницу.
2. Видит hero-блок, живой коллаж фотографий и количество вещей.
3. Ниже отображается сетка карточек с бесплатными объявлениями.
4. Клик по карточке открывает модальное окно с деталями.

### Фильтрация по категориям

Категории находятся в sticky-панели под hero:

- Всё;
- Мебель;
- Животные;
- Техника;
- Детям;
- Одежда;
- Растения;
- Разное.

При клике на категорию перерисовываются лента и точки на карте.

### Поиск

Поле поиска фильтрует объявления по названию и рубрике. Поиск работает на клиенте по массиву `items`.

### Просмотр объявления

В модальном окне объявления показываются:

- галерея фотографий;
- название;
- категория, район, дата, просмотры и количество фото;
- описание;
- данные отдающего;
- рейтинг, если он есть;
- кнопки бронирования и перехода к исходному объявлению.

### Paywall и демо-оплата

Бронь и переход к исходному объявлению закрыты paywall-сценарием:

1. Пользователь нажимает «Забронировать» или «Открыть объявление».
2. Если подписка не активирована, открывается окно «Урви+».
3. Пользователь выбирает месячный или годовой тариф.
4. Отправка формы имитирует оплату через `setTimeout`.
5. После успешной демо-оплаты включается флаг `subscribed = true`, появляется бейдж «Урви+», а отложенное действие выполняется автоматически.

Важно: реальные деньги не списываются, платежного провайдера нет.

### Бронирование

После активации подписки пользователь может забронировать вещь. Открывается модальное окно с:

- телефоном отдающего в маскированном формате;
- районом самовывоза;
- ссылкой-заглушкой «Построить маршрут»;
- таймером на 15 минут.

Таймер работает только в текущей вкладке и не сохраняется после перезагрузки.

### Карта

Карта построена на Leaflet и OpenStreetMap. Координаты не являются реальными адресами объявлений: они вычисляются из района и индекса объявления, чтобы получить визуально разные точки внутри Махачкалы.

## 7. Архитектура `urvi-prototype.html`

Файл состоит из четырех крупных частей:

1. `head` — метаданные, подключения шрифтов, Leaflet и CSS.
2. `style` — вся визуальная система и адаптивные стили.
3. `body` — разметка страницы, модальных окон и toast-уведомления.
4. `script` — мок-данные и клиентская логика.

### Основные блоки интерфейса

| Блок | Описание |
|---|---|
| Header | Логотип, поиск, город, вход, кнопка «Отдать вещь». |
| Hero | Главный оффер, CTA, счетчик объявлений, анимированный фотоколлаж. |
| Category chips | Горизонтальные фильтры категорий. |
| Grid | Карточки объявлений. |
| Map section | Карта с точками объявлений и popup-карточками. |
| Promo | Промо-блок подписки «Урви+». |
| Footer | Бренд, дата данных, копирайт. |
| Modals | Детали объявления, paywall, успешная бронь. |
| Toast | Короткие системные уведомления. |

## 8. Данные

Основные данные загружаются из Supabase REST API. В константе `items` внутри `<script>` сохранён локальный fallback-набор из первоначального прототипа: он используется только если запрос к Supabase завершится ошибкой.

Каждый объект объявления содержит:

| Поле | Значение |
|---|---|
| `t` | Название объявления. |
| `url` | Ссылка на исходное объявление Avito. |
| `cat` | Внутренняя категория для фильтра. |
| `rcat` | Оригинальная рубрика объявления. |
| `e` | Emoji-иконка категории. |
| `area` | Район Махачкалы. |
| `ago` | Время публикации в текстовом формате. |
| `desc` | Описание объявления. |
| `photos` | Массив URL фотографий. |
| `pc` | Количество фото. |
| `seller` | Имя или тип продавца. |
| `stype` | Тип продавца. |
| `rate` | Рейтинг, если есть. |
| `views` | Количество просмотров в текстовом формате. |
| `phone` | Маскированный телефон для сценария брони. |

CSV-объявления были нормализованы через `prepare_supabase_seed.js` и загружены в Supabase вместе с исходными объявлениями из HTML. Автоматического регулярного парсинга пока нет.

## 10. Состояние приложения

Основное состояние хранится в глобальных переменных:

| Переменная | Назначение |
|---|---|

## 11. Визуальная система

CSS построен на переменных в `:root`:

- фон: `--bg`;
- поверхность: `--surface`;
- основной текст: `--ink`;
- вторичный текст: `--ink-2`, `--muted`;
- линии: `--line`, `--line-2`;
- брендовый зеленый: `--brand`, `--brand-ink`, `--brand-soft`, `--brand-2`;
- акцентные цвета: `--amber`, `--red`, `--blue`;
- радиусы и тени: `--r`, `--r-sm`, `--sh-1`, `--sh-2`, `--sh-3`.

Интерфейс адаптивный:

- до `1080px` сетка становится трехколоночной;
- до `860px` hero перестраивается в одну колонку;
- до `760px` header переносит поиск на отдельную строку, сетка становится двухколоночной, модальное окно объявления становится одноколоночным;
- до `420px` уменьшается размер hero-заголовка.

## 12. Ограничения текущего прототипа

- Нет backend и реального API.
- Нет отдельного backend-приложения; чтение объявлений идёт напрямую через Supabase Data API.
- Нет авторизации пользователей.
- Нет реальной оплаты.
- Нет реального бронирования на стороне сервера.
- Нет проверки актуальности объявлений.
- Нет регулярного парсинга Avito, VK, Telegram или других источников.
- Нет юридической модели использования данных внешних площадок.
- Координаты на карте демонстрационные.
- Фотографии грузятся с внешних URL и могут пропасть.
- Некоторые кнопки являются заглушками: «Войти», «Отдать вещь», «Построить маршрут».
- Сортировка в выпадающем списке визуальная, фактическая логика сортировки не реализована.

## 13. Что нужно для превращения в реальный продукт

### Frontend

- Разделить монолитный HTML на компоненты.
- Перенести проект в React, Vue, Svelte или другой выбранный стек, если нужен масштабируемый frontend.
- Вынести мок-данные из HTML в API-слой.
- Добавить реальные состояния загрузки, ошибок и пустых экранов.
- Реализовать настоящую сортировку.
- Добавить сохранение избранного.

### Backend

- Спроектировать API объявлений.
- Добавить базу данных.
- Хранить пользователей, подписки, избранное, брони и историю действий.
- Сделать дедупликацию объявлений из разных источников.
- Реализовать статусы объявлений: доступно, забронировано, забрали, устарело, жалоба.

### Сбор данных

- Определить легальные источники данных.
- Проверить правила Avito, VK, Telegram и других площадок.
- Сделать парсер или официальные интеграции там, где это разрешено.
- Добавить нормализацию категорий, районов, времени публикации и контактов.
- Настроить периодическое обновление и удаление устаревших объявлений.

### Монетизация

- Подключить реальный платежный провайдер.
- Разделить бесплатные и платные возможности.
- Добавить управление подпиской.
- Сделать честный onboarding без завышенных демо-обещаний.

### Безопасность и доверие

- Модерация объявлений.
- Жалобы и блокировки.
- Рейтинги и репутация отдающих.
- Защита от фейковых объявлений.
- Предупреждения по самовывозу и встречам.

## 14. Рекомендованный следующий этап

Наиболее рациональный следующий шаг — выделить проект из статического прототипа в минимальное приложение:

1. Создать структуру frontend-проекта.
2. Вынести объявления в отдельный JSON или mock API.
3. Разбить интерфейс на компоненты: header, hero, filters, listing grid, item modal, paywall, map.
4. Добавить простое локальное состояние и хранение подписки/избранного в `localStorage`.
5. После этого проект будет готов к подключению реального API и backend.
